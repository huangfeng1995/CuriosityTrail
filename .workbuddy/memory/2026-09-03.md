## PDF 按内容规则拆分工具（pdf_split/）

参考用户提供的 PySide6 材料 `import pfd sys PDF.py`（业务标签：开票申请单、费用签审单、验收申请等 12 类），
实现按内容自动识别分界点拆分 PDF。

- 主程序 `pdf_split/pdf_splitter.py`，规则 `rules.example.json`，样本与校验脚本在 `samples/`
- **技术选型：PyMuPDF（fitz），不用原材料里的 pypdf**。原因：pypdf 的 add_page 会丢 AcroForm 表单域/批注，
  insert_pdf 是页面对象级复制；且本机 miniconda 只有 PyMuPDF 1.27.2，没有 pypdf 也没有 PySide6，原材料跑不起来
- 识别路径：PDF 书签 → keyword → regex → blank_page，每页最多一个分界点，书签优先
- 关键设计：区间首尾相接保证页数守恒，verify() 不通过则终止写盘；`--dry-run` 预览；
  输出 `_manifest.json` 记录每段页码/命中文本/note
- 踩坑：续页标题「费用签审单（续1）」会被误判为新分界点 → 加 exclude 正则（规则级 + 全局级）
- 原材料缺陷：FIXED_TAGS 中「服务通知单」重复；未绑定页不导出会丢页；区间重叠只警告不拦截

## 交付形态改为网页工作台（pdf_workbench/）

用户明确要求"最终产出应该是一个完整的网页端工作台"，CLI 只是中间产物。已删除 pdf_split/。

架构：**网页工作台 + 本机 Python 服务**（纯前端 pdf-lib 做不了页内内容裁切，无法改写页面内容流）。

```
pdf_workbench/
  start.bat              一键启动（自动装依赖+开浏览器），走 py/python 探测
  server.py              标准库 ThreadingHTTPServer，仅监听 127.0.0.1，端口 8765-8785
  core/splitter.py       拆分引擎（也可命令行用）
  web/index.html         单文件全内联零外链，四模块：预览/规则/分段校正/导出
  rules.example.json     12 类材料标签；rules_inline.json 演示页内切分
```

API：open / thumb / rules / detect / rebuild（校正后重算）/ export / file（下载）
前端只维护 boundaries 列表，所有分段计算都在服务端——校正后调 rebuild 实时刷新。

### 两级分界（用户确认"一页内多个材料"的情况确实存在）
- 页级：命中页整体作段首，页数守恒
- 页内：`page.search_for()` 定位命中 y 坐标 → `show_pdf_page`+clip 纵向裁开，一页变两块
- 关键：**同一页允许多个分界点**（原设计一页一个，导致第二条规则永远不生效）
- 开启 inline 的规则必须 scope=page，否则只在页首区域查找
- 页内切分后输出页数 > 原页数，与"页数守恒"存在固有冲突 → 校验改为按页纵向覆盖率
  （每页 [0,h] 被 block 严丝合缝铺满），页级模式仍要求页数之和 == 原页数

### 踩坑记录
- `_blocks_between` 末段漏掉最后一页 → 末段（end is None）必须补 append 末页整页
- f-string 内嵌套转义引号 `f'{s[\"k\"]}'` 在 3.12 以下报语法错 → 改用 % 格式化
- `filename*=UTF-8''` 后要跟 `quote(name)` 百分号编码，不是 hex
- 覆盖率校验抓出了上面第一个 bug，这类"不重不漏"断言非常值得保留
