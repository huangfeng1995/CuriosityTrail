## 二、A 需求池（近期体验与功能）

### A1 资料员能收集的专业内容太少
- 状态：**未设计**
- 现状：检索词只用作者原句做 bigram；召回写死站内 4 + 联网 4；联网只抓第 1 条正文；站内片段 160 字；来源不分级；扫描版 PDF 静默不可搜
- 阻塞：**专业内容从哪来**——深挖现有来源，还是引入专业语料库（成本差一个数量级）
- 依赖：若走「多轮扩检」，依赖 C1 的技能机制（已具备）

### A2 专注模式
- 状态：**未设计**
- 现状：store 无布局状态字段；`useColumnWidths` + `Resizer` 现成；侧栏收起已由 A6 实现
- 阻塞：专注到什么程度——只藏 AI 栏，还是单栏纯正文
- 已知要求：必须有键盘出口（`Esc` / `Cmd+.`）；状态存 localStorage（跟设备走）

### A3 阅读模式 / 作品分享
- 状态：**未设计**，**从零做**
- 现状：无阅读视图、无公开路由、无分享数据模型；导出模块（`routes/export.js`）已有块→段落与 markdown 结构可复用
- 阻塞：粒度（单章 / 整部 / 片段）+ 权限（持链接可看 / 公开）+ 静态成品还是活页面
- 硬约束：绝不能把 AI 引用、批注、草稿历史、账号信息带出去

### A4 多用户 key / 用量配额
- 状态：**未设计**；**安全口子仍在**（`PUT /api/ai` 登录即可改全站 key）
- 现状：AI 配置是进程级单例、明文 key、无 userId；用户表无 key/配额/用量；`chatStream` 已采 usage 但未落库；无 `api_usage` 表
- 阻塞：key 模式——平台统一 / 作者自带（BYOK）/ 混合
- 分三步：① 收 admin-only（几行）② `api_usage` 表 + usage 落库 ③ BYOK + 归属校验 + 设置页页签

### A5 编辑区水平方向太窄
- 状态：**未做**
- 现状：正文容器写死 `max-width: 960px`（`web/client/src/styles/theme.css` L1468-1474）
- 要求：随视口加宽；改完回归稿纸格线对齐（34px 整数倍）与光标不跳底
- 备注：与 A6 同属一片前端布局

### A6 编辑区两侧栏可隐藏
- 状态：**已完成**（Agent 技能计划 Task 6）
- 落地：`COLLAPSE_KEY` 持久化、左右栏独立收起、折叠按钮、展开按钮
- 遗留：侧栏收起后 textarea 高度重算（ResizeObserver）需确认已覆盖

### A7 审稿意见 → 写手重写报「模型这次没有返回内容」
- 状态：**未排查**
- 现象：手动复制同样内容给写手能重写成功 → 问题在自动链路的上下文/参数，不是模型能力
- 排查线索：审稿意见是否被拼进写手请求；重写时 `target` / 章节是否为空；`reasoning` 是否传到 `describeEmptyReply`；前端是否覆盖了后端报错
- 额外要求：「只思考无正文」与「真空响应」分开报错
